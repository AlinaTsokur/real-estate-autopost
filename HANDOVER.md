# Передача проекта: что это, как устроено и как включить другие эмираты

Документ для человека, который принимает эту систему. Написан так, чтобы можно было
читать без предварительного знания проекта. Дата: 15.08.2026.

---

## 0. Одним абзацем

Это одно веб-приложение (Next.js), которое живёт на Vercel и помогает маркетингу
Prime Bridge: собирает посты по объектам и отправляет их в Telegram и WhatsApp,
делает рассылки по группам, готовит каталог для Meta, следит за сроками пермитов
и напоминает брокерам про их листинги. Данные об объектах оно **только читает**
из базы IT-команды — ничего своего про юниты не хранит.

Сейчас всё, что касается объектов, жёстко ограничено **Абу-Даби**. Дубай и RAK
в базе уже есть, но код их отфильтровывает. Ниже — что именно нужно сделать,
чтобы они появились.

**Боевой адрес:** https://real-estate-autopost.vercel.app
**Код:** GitHub `AlinaTsokur/real-estate-autopost`, ветка `main`.
Пуш в `main` → Vercel сам собирает и выкладывает. Отдельной команды на деплой нет.

## 1. Что уже есть

### 1.1 Откуда берутся данные

Источников три вида, и это важно понимать, потому что «поменять эмират» —
это в первую очередь вопрос про данные, а не про код.

| Источник | Что там лежит | Права | Переменная |
|---|---|---|---|
| **База IT-команды** (Neon Postgres) | Юниты, проекты, здания, районы, брокеры, цены, статусы. Главный источник правды | **Только чтение.** Все запросы идут в транзакции `READ ONLY` — Postgres отклонит даже случайную запись | `UNITS_DB_URL` |
| **Наша база «meta»** (Neon, us-east-1) | Смайлики и папки фото проектов (`project_emoji`), очередь отложенных отправок WhatsApp (`wa_queue`), каталог Meta (`catalog_items`), лог сверки брокеров (`broker_check_log`, `broker_check_optout`) | Чтение и запись | `META_DB_URL` |
| **Наша база «wa»** (Neon, eu-central-1) | WA Монитор: заявки от брокеров (`wa_requests`), триггерные фразы (`wa_triggers`), подключённые номера (`wa_instances`) | Чтение и запись | `DATABASE_URL` |
| **Google-таблица «Объявления Абу-Даби»** | Лист `Abu Dhabi` — рабочая таблица объявлений (дата объявления, подтверждение цветом, аренда). Ещё листы: `C3 Garden Res`, `Брокеры`, `CONFIG_DRIVE`, `WA Weekly Check` и рабочие листы коллег | Чтение и запись | `GOOGLE_SHEETS_OBJECTS_ID` |
| **Google-таблица «Копия»** | Листы `OBJECTS` (данные C3) и `PROJECT_PARSE_CONFIG` (как разбирать проект). Листы `CONFIG`, `CONFIG2`, `CATALOG`, `WA_QUEUE` приложение **больше не читает** — их содержимое переехало в базы, но сами листы никто не удалял | Чтение | `GOOGLE_SHEETS_CONFIG_ID` |
| **Google-таблица «Permit»** | Лист `Prime Bridge` — сроки окончания пермитов | Чтение | ID зашит прямо в коде: `src/app/api/cron/permit-expiry/route.ts:4` |

Внешние сервисы: **Telegram** (бот + канал + личная MTProto-сессия для поиска
старых постов), **Green API** (отправка WhatsApp), **Canva** и **iLovePDF**
(презентации и сжатие PDF).

### 1.2 Инструменты

Меню слева — это и есть список инструментов. Плюс несколько страниц, которых
в меню нет, но они рабочие.

| Адрес | Название | Что делает | Завязка на Абу-Даби |
|---|---|---|---|
| `/manual-post` | Посты | Выбираешь проект и юнит → собирается готовый текст поста для Telegram и WhatsApp, картинка/планировка, отправка в канал, отметка «дата объявления» в таблице | **Да** — в выпадающих списках только юниты АД |
| `/budget` | Рассылки | Две утренние рассылки. **Budget Units** — по выбранному проекту собирает из базы список доступных юнитов: тип, вид или положение дома в ряду, площадь в кв. метрах и кв. футах, цена (старая цена печатается, только если она была выше нынешней). **Quick Sales** — срочные продажи (`deal_type = Distress Deal`) по всем проектам сразу, сгруппированные по проектам. Текст можно поправить руками, отметить группы WhatsApp и задать время старта — отправка встаёт в очередь и уходит по расписанию. Проекты, по которым рассылка уже была, помечаются кружком | **Да** — список групп зашит в коде, все группы про АД |
| `/quick-sales` | — | Та же рассылка Quick Sales отдельной страницей, в меню её нет | **Да** — выборка и группа `Hot deals in abu dhabi` |
| `/catalog` | Каталог | Карточки объектов для Meta Commerce Manager. Наружу отдаётся по постоянному адресу `/api/catalog-feed` | **Да** — город, регион и координаты зашиты как Abu Dhabi |
| `/drive-audit` | Аудит Drive | Проверяет, что папки юнитов в Google Drive лежат в правильном месте согласно статусу | **Да** — читает лист `Abu Dhabi` |
| `/wa-monitor` | WA Монитор | Ловит входящие сообщения брокеров через вебхук Green API, распознаёт заявки по триггерным фразам и напоминает ответить | Нет |
| `/plan-crop` | Кадр планировок | Кадрирование картинок под пост | Нет |
| `/project-emoji` | Проекты | Смайлик проекта для постов и ссылка на папку с фото. Список проектов приезжает кроном | **Да** — синхронизируются только проекты АД |
| `/no-posts` | Юниты без постов | Доступные юниты, по которым ещё ни разу не делали пост | **Да** |
| `/broker-check` | Сверка брокеров | Еженедельная рассылка брокерам со списком их листингов: «актуально ещё?». Есть рубильник, лог отправок и отписки | **Да** |
| `/scheduled` | — | Очередь отложенных отправок WhatsApp: что и когда уйдёт | Нет |
| `/reduced-price` | — | Пост об изменении цены со зачёркнутой старой | Нет |
| `/c3-autopost`, `/canva-weekly` | — | Отдельная история про проект C3 Garden Residence и еженедельные презентации Canva | Нет |

### 1.3 Что работает само, без человека

| Что | Когда | Где настроено |
|---|---|---|
| Напоминание об истекающих пермитах в Telegram | каждый день 06:00 | `vercel.json` → `/api/cron/permit-expiry` |
| Обновление списка проектов из базы IT | каждый день 05:30 | `vercel.json` → `/api/project-sync` |
| Отправка отложенных сообщений WhatsApp | по расписанию | `/api/cron/wa-send` — **запускается внешним пингером, не Vercel** |
| Напоминания WA Монитора | раз в час | `/api/wa-monitor/cron` — **см. раздел 5, сейчас не работает** |
| Приём входящих WhatsApp | постоянно | вебхук Green API → `/api/wa-monitor/webhook` |
| Кнопки под постами в Telegram | постоянно | вебхук бота → `/api/telegram/webhook` |

      аккаунте Алины. Нужно либо перенести его на аккаунт компании
      (Settings → Transfer ownership), либо добавить нового человека в
      коллабораторы. **Важно:** после переноса проверить, что Vercel не потерял
      связь с репозиторием.
- [ ] **Vercel** — проект `real-estate-autopost` в скоупе «Tsokurenok's projects»,
      аккаунт `a.tsokur@primebridge.estate` (рабочая почта, остаётся у компании).
      План Hobby. Нужен доступ к этой почте или перенос проекта.
- [ ] **База IT-команды** — строка подключения `UNITS_DB_URL`. Владелец — IT-команда,
      просить у них. Доступ только на чтение, так и должно быть.
- [ ] **Две наши базы Neon** (`META_DB_URL`, `DATABASE_URL`) — выяснить, на какой
      аккаунт Neon они заведены, и передать этот аккаунт. Если он личный —
      перенести проекты в организацию.
- [ ] **Google** — один OAuth-клиент и refresh-токен (`GOOGLE_CLIENT_ID`,
      `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`). Токен выпущен от конкретного
      гугл-аккаунта, и от него же зависят права на таблицы и Drive. Если аккаунт
      личный — перевыпустить от рабочего, иначе всё отвалится в день отключения
      учётки.
- [ ] **Telegram** — бот (`TELEGRAM_BOT_TOKEN`), канал (`TELEGRAM_CHANNEL_ID`),
      два служебных чата (`TELEGRAM_REVIEW_CHAT_ID`, `TELEGRAM_SEARCH_CHAT_ID`).
      Плюс **MTProto-сессия** (`TELEGRAM_SESSION`, `TELEGRAM_BOT_SESSION`,
      `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`) — это вход в личный аккаунт Telegram
      живого человека, нужен для поиска старых постов. **Обязательно перевыпустить
      на нового сотрудника**, иначе поиск перестанет работать (или продолжит
      работать от лица уволившегося, что ещё хуже).
- [ ] **Green API** — `GREENAPI_ID_INSTANCE`, `GREENAPI_API_TOKEN`. Инстанс привязан
      к конкретному номеру WhatsApp. Дополнительные номера для WA Монитора лежат
      в базе, таблица `wa_instances`.
- [ ] **Canva и iLovePDF** — ключи есть в локальном `.env.local`, но **на боевом
      сервере не заведены**, поэтому эти функции в проде не работают. Решить,
      нужны ли вообще.
- [ ] **`CRON_SECRET`** — пароль, которым подписаны запросы к кронам.

Все боевые значения лежат в Vercel → Project → Settings → Environment Variables.
Выгрузить их себе: `vercel env pull .env.local`.

## 3. Другие эмираты: главное, что нужно понять

### 3.1 Данные уже есть

В базе IT-команды эмират — это просто колонка `emirate` у юнита и у проекта.
Возможных значений три: `Abu Dhabi`, `Dubai`, `RAK`. На момент написания:

| Эмират | Доступных юнитов | Проектов (активных) |
|---|---|---|
| Abu Dhabi | 343 | 40 |
| Dubai | **197** | **7** |
| RAK | 3 | 3 |

То есть Дубай уже полностью заведён коллегами — приложение его просто не показывает,
потому что в каждом SQL-запросе стоит условие `emirate = 'Abu Dhabi'`.

### 3.2 Нужно ли копировать код и делать второе приложение

**Нет.** Не надо ни форкать репозиторий, ни поднимать второй проект на Vercel,
ни копировать базу. Это создало бы две копии одного и того же кода, которые
дальше расходятся, и любое исправление пришлось бы делать дважды.

Правильный путь: работать в этом же репозитории и превратить эмират из зашитой
константы в **параметр**. Приложение остаётся одно, а на экране появляется
переключатель «Абу-Даби / Дубай».

Работа делается в отдельной ветке (`git checkout -b dubai`), проверяется на
превью-адресе, который Vercel выдаёт автоматически, и только потом вливается в `main`.

## 4. Пошаговый план: как включить Дубай

### Шаг 1. Снять фильтр по эмирату (около дня работы)

Одиннадцать мест, где зашито `'Abu Dhabi'`. Во всех — добавить аргумент
`emirate` со значением по умолчанию `'Abu Dhabi'`, чтобы ничего не сломать сразу.

| Файл | Строки | Что там |
|---|---|---|
| `src/lib/units-db/units.ts` | 19, 31, 44, 72, 137, 165, 194, 222 | Восемь запросов: список проектов, юниты без постов, поиск, каталог, бюджет, срочные продажи, один юнит |
| `src/lib/broker-check/brokers.ts` | 85, 152 | Выборка для сверки брокеров и списки ассистентов/менеджеров |
| `src/lib/post-meta/project-config.ts` | 30 | Поиск проекта по названию с приоритетом Абу-Даби |

⚠️ **Ловушка в `project-config.ts:30`.** Проект ищется по названию, и если
одинаково названные проекты есть в разных эмиратах, сейчас всегда побеждает
абудабийский. Когда включите Дубай, надо будет искать по паре
«название + эмират», иначе в дубайский пост подставится абудабийский остров
и смайлик. Это самое неочевидное место во всей задаче.

### Шаг 2. Дать выбор эмирата в интерфейсе

Самый простой вариант, который не ломает привычки: переключатель в шапке
(`src/app/layout.tsx`), значение хранится в адресе страницы — `?emirate=Dubai`.
Тогда ссылку на «дубайский» экран можно кинуть коллеге, и он откроется как надо.

### Шаг 3. Что придётся завести руками — это не код, а данные и настройки

Самая недооценённая часть. Кода тут почти нет, но без этого Дубай будет
работать наполовину.

| № | Что | Как сейчас | Что сделать |
|---|---|---|---|
| 1 | **Смайлики и папки с фото у проектов** | Таблица `project_emoji` в нашей базе, 43 строки. Наполняется кроном `/api/project-sync`, который берёт **только проекты АД** | Расширить крон на нужный эмират, потом зайти на `/project-emoji` и проставить смайлики и ссылки на папки для 7 дубайских проектов |
| 2 | **Группы WhatsApp для рассылок** | Список из 10 групп зашит в `src/app/budget/page.tsx:8-17`, ещё одна в `src/app/quick-sales/page.tsx:8`. Все — про Абу-Даби | Собрать дубайские группы, добавить к каждой пометку эмирата. Лучше сразу вынести список в базу, чтобы не править код при каждой новой группе |
| 3 | **Канал Telegram** | Один на всё, `TELEGRAM_CHANNEL_ID` | Решить: тот же канал или отдельный для Дубая. Если отдельный — добавить вторую переменную и выбирать по эмирату |
| 4 | **Рабочая Google-таблица** | Таблица называется «Объявления Абу-Даби», лист `Abu Dhabi`. В него ставится дата объявления и подтверждение цветом. Имя листа зашито в 5 местах: `src/lib/google/sheets.ts:53,95`, `src/app/api/unit-lookup/route.ts:44`, `src/app/api/audit/drive-folders/route.ts:27,101` | Завести лист `Dubai` с теми же колонками и выбирать лист по эмирату. Колонки берутся по заголовкам, а не по буквам, так что порядок столбцов может отличаться — но названия должны совпадать |
| 5 | **Каталог для Meta** | `src/lib/catalog/store.ts:56-60`: город, регион и координаты жёстко Abu Dhabi для всех карточек | Сделать словарь «эмират → город, регион, координаты» |
| 6 | **Пермиты** | Отдельная таблица «Permit», лист `Prime Bridge`, ID зашит в `src/app/api/cron/permit-expiry/route.ts:4`. Крон каждый день в 06:00 сравнивает дату окончания с сегодняшней | В Дубае разрешения на рекламу выдаёт другой регулятор и правила отличаются — сначала выяснить у отдела, как они это ведут, и только потом решать: добавить колонку «эмират» в тот же лист или завести второй |
| 7 | **Тексты постов** | «Quick Sales \| Abu Dhabi» в `src/lib/posts/budget.ts:94` | Подставлять название эмирата |
| 8 | **Папки в Google Drive** | Аудит папок сделан под структуру Абу-Даби, справочник в листе `CONFIG_DRIVE` | Завести дубайские папки и дописать справочник |

Про «остров» в постах: он берётся из справочника районов базы IT
(`districts.name`), а не из нашего кода. Для Дубая там будут районы вместо
островов — код менять не нужно, но стоит посмотреть глазами, как это читается
в готовом посте.

### Шаг 4. В каком порядке и как проверять

1. Сначала то, что **только читает**: `/no-posts`, `/manual-post`, `/catalog`.
   Здесь ничего никуда не уходит, ошибиться безопасно. Открываете Дубай,
   смотрите, что юниты находятся и текст поста собирается правильно.
2. Потом **смайлики и папки** (пункт 1 из таблицы выше) — без них посты выйдут
   некрасивыми.
3. И только потом то, что **отправляет наружу**: рассылки, сверка брокеров,
   каталог в Meta. Первую отправку сделать в тестовую группу, а не в боевую.

## 5. Что сломано или недоделано прямо сейчас

Честный список, чтобы не пришлось выяснять самому.

1. **Последний коммит не выложен на боевой.** В `main` лежит коммит `a98180d`
   («Напоминания WA Монитора: добавить крон»), а на Vercel самое свежее — `fb90145`.
   Деплоя этого коммита нет вообще, даже неудачного: похоже, Vercel не получил
   уведомление от GitHub. Проверить связь репозитория в Settings → Git и запустить
   сборку заново.
2. **Крон WA Монитора не запущен.** В `vercel.json` их три, а Vercel зарегистрировал
   только два (`permit-expiry` и `project-sync`). Причина в тарифе: на плане Hobby
   Vercel не даёт больше двух кронов и запускает их не чаще раза в сутки. Поэтому
   почасовой `/api/wa-monitor/cron` там просто не появится. Варианты: перейти на
   платный план или дёргать его снаружи, как уже сделано для отправки отложенных
   сообщений.
3. **Приложение открыто всем.** Пароля или входа нет — кто знает адрес, тот зайдёт
   и сможет отправить рассылку. Стоит хотя бы включить Vercel Deployment Protection
   или добавить простой пароль, как в соседнем проекте.
4. **Canva и iLovePDF на боевом не настроены** — ключей в переменных окружения нет,
   соответствующие страницы работать не будут.
5. **На главной странице врёт описание.** Плитка «Budget Builder» обещает расчёт
   первого взноса и плана «1% в месяц» (`src/app/page.tsx:39`) — такого в системе
   нет и никогда не было, это осталось от самого первого варианта сайта. Заодно
   на главной вообще нет половины инструментов. Проще всего переписать её под
   реальный список из меню.
6. **README пустой** — там до сих пор стандартный текст Next.js. Этот документ
   заменяет его по смыслу.
7. **Папка `legacy-appscript`** — старые скрипты Google Apps Script, из которых
   выросло приложение. Они уже не используются, лежат для истории.

## 6. Как запустить у себя на компьютере

```bash
git clone https://github.com/AlinaTsokur/real-estate-autopost.git
cd real-estate-autopost
npm install

# забрать боевые переменные окружения (нужен доступ к проекту на Vercel)
npx vercel link
npx vercel env pull .env.local

npm run dev          # откроется http://localhost:3000
```

Локально приложение работает с **боевыми** базами и боевым WhatsApp — то есть
кнопка «отправить» отправит по-настоящему. Перед экспериментами замените в
`.env.local` идентификаторы групп и каналов на тестовые.

Важное правило проекта записано в `AGENTS.md`: версия Next.js здесь новая,
и часть привычных приёмов в ней уже не работает. Прежде чем писать код, стоит
заглянуть в документацию, которая лежит прямо в проекте:
`node_modules/next/dist/docs/`.

## 7. Словарик

- **Юнит** — конкретная квартира или вилла. У него есть код вида `040·01·001`:
  первые три цифры — проект, следующие две — здание, последние — номер юнита.
- **Проект** — жилой комплекс.
- **Пермит** — разрешение на рекламу объекта, у него есть срок годности.
- **Distress Deal** — так в базе называется срочная продажа; в постах и рассылках
  это «Quick Sale».
- **Фид** — файл со списком объектов, который Meta забирает по адресу
  `/api/catalog-feed`, чтобы показывать карточки в рекламе.
- **Green API** — сервис-посредник, через который приложение пишет в WhatsApp.
- **MTProto-сессия** — сохранённый вход в личный аккаунт Telegram; нужен для того,
  чего не умеет обычный бот (например, найти старый пост в канале).
